# 招聘平台自动打招呼助手（Tampermonkey）

![版本](https://img.shields.io/badge/%E7%89%88%E6%9C%AC-v1.10.31-2ea44f) ![支持平台](https://img.shields.io/badge/%E6%94%AF%E6%8C%81%E5%B9%B3%E5%8F%B0-BOSS%20%C2%B7%20%E6%99%BA%E8%81%94%20%C2%B7%20%E9%B1%BC%E6%B3%A1-orange) ![运行环境](https://img.shields.io/badge/%E8%BF%90%E8%A1%8C%E7%8E%AF%E5%A2%83-Tampermonkey-blueviolet) ![语言](https://img.shields.io/badge/%E8%AF%AD%E8%A8%80-JavaScript-f7df1e)

面向 BOSS直聘、智联招聘、鱼泡直聘的自动沟通脚本。脚本在页面右下角生成可拖动配置面板，按页面列表顺序依次处理职位：定位职位、切换右侧详情、点击沟通按钮、等待聊天界面、写入选中的预设话术并发送；达到设定成功数量后立即停止。支持自动识别并跳过「已沟通」职位，也可以关闭自动打招呼，只保留职位切换与已沟通跳过流程。

## ⚡ 快速开始

| 步骤 | 操作 |
| --- | --- |
| ① 安装扩展 | 电脑端 Chrome / Edge 安装 Tampermonkey 扩展（应用商店搜索「Tampermonkey」） |
| ② 安装脚本 | 打开 [脚本安装直链](https://raw.githubusercontent.com/yjw2104425795/job-auto-greet-v1.10.5-release/main/job-auto-greet.v1.10.31.user.js) 全选复制 → Tampermonkey 图标 →「添加新脚本」→ 粘贴全部内容 → `Ctrl + S` 保存并启用 |
| ③ 打开列表页 | 登录 BOSS直聘 / 智联招聘 / 鱼泡直聘，进入职位搜索结果页（支持页面见下文） |
| ④ 开始运行 | 页面右下角出现「自动沟通助手」面板 → 选择预设话术、设置处理数量 → 点「开始」；已沟通职位自动跳过，达标自动停止 |

> ⚠️ 脚本会在您的账号上产生**真实沟通消息**：首次体验建议把「处理数量」设为 1~2、「操作间隔」不低于 3 秒；体验前请阅读文末「风控与使用建议」。

## 支持页面

脚本在下列页面显示面板，其他页面不会注入 UI：

- BOSS直聘：`https://www.zhipin.com/web/geek/jobs?...`、`/web/geek/job`，以及跨页流程使用的聊天页 `/web/geek/chat`
- 智联招聘：`https://www.zhaopin.com/jobs/?...`（兼容 `sou.zhaopin.com` 列表页）
- 鱼泡直聘：`https://www.yupao.com/topic/...`（兼容 `/zhaopin/`、`/joblist`、`/search` 开头的列表页）

使用前请先登录对应平台。未登录时，平台通常会弹出登录或验证码浮层，脚本会停止并提示先登录，不会尝试绕过验证。智联「设置招呼语」页面不会注入面板，避免误触「添加招呼语 / 设为默认」导致自动发送。

## 功能概览

- **按列表顺序批量沟通**：三个平台的卡片统一按页面文档位置从上到下处理，面板日志显示「第 N/总数 条」。
- **区间扫描**：可指定「第 N~M 条」区间，只扫描该区间内的职位，避免每次都从头遍历；与「循环模式（按处理数量）」互斥，面板同时只能开启一项。
- **BOSS 已操作标记**：BOSS 点击「立即沟通」前把职位写入本地持久化标记；从独立聊天页返回列表页或下次重新开始时，自动跳过已标记职位。
- **BOSS 聊天页自动返回**：聊天页发送完成后按开始时的列表完整地址（含筛选参数）显式返回，并恢复滚动位置，随后自动续跑下一职位；可在面板关闭。
- **平滑速率控制（防风控）**：不规则随机间隔 + 点击前人工行为模拟（悬停 / 微滚动 / 停顿）+ 连续异常自动降速 + 周期性长休息；三项可独立开关，默认全开。
- **严格卡片点击间隔**：「操作间隔」按「上一张职位卡片点击结束 → 下一张卡片点击开始」计算，跳过路径与 BOSS 跨页同样遵守。
- **紧凑配置面板**：核心操作常驻，预设管理、扫描范围、速率控制等收纳为折叠分组；实测默认高度由 992px 降至 497px（减少 49.9%）。
- **BOSS 发送对象强绑定**：聊天页填写/发送前校验当前会话与目标职位一致，不一致时停止发送，避免把打招呼发给上一职位的 HR（v1.10.28 起列表侧不再做「右侧详情与当前职位」严格比对，避免误跳过未沟通职位）。v1.10.29 起该校验为面板可选开关「BOSS 会话与职位校验」，默认开启，关闭后跳过校验直接填入发送，适合详情页与列表项存在正常差异、被误跳过的场景。
- **BOSS 输入精确校验**：聊天页填入前先清空草稿/上次未发内容，填入后按精确等值校验并同步 React 状态；发送前再次校验，重复/追加内容一律不发送。同时用消息气泡数变化识别「已发送但输入框未清空」，避免回车重发造成重复消息；面板可关闭。
- **智联结果弹窗自动关闭**：点击「先聊聊」后按稳定结构（`deliver-greeting-modal__box` 结果框 + `__close`/`__btn` 按钮）优先定位「已向对方发送打招呼」弹层；「留在此页」按钮与「×」关闭按钮两种方式交替重试，点击前显式等待弹窗完全加载且目标可交互，单次点击异常自动换另一种方式兜底，全部走原生 `.click()`（合成点击会被智联门禁丢弃）；closeChat 后弹窗仍残留时守卫复核并改走两方式链路；每轮开始前清理残留弹窗并等待遮罩完全消散，避免拦截后续卡片点击；面板可关闭该兜底开关。
- **BOSS 动态元素定位**：区间目标改为启动时的职位 key 快照（pathname），后续按元素重新定位而不是实时下标；返回列表后已沟通职位被动态移除、列表前移也不会错位或越界。
- **跨页续跑修正**：第 2 个职位起，跳转聊天页前不再把流程误标为完成，聊天页可正常接管发送。
- **鱼泡发送按钮适配**：点击「免费聊」打开右侧聊天窗后，若预设文本已写入但发送按钮仍为灰色，脚本会补发输入事件并解除禁用状态，确保内容能正常发出。
- **鱼泡输入同步增强**：先解析真正的可编辑节点（`.fb-editor` 可能只是外层容器），用 `execCommand` 走浏览器编辑管线，补发 `beforeinput/input/change/keydown/keypress/keyup`，并直调 Vue `_vei` / React `onChange` 等输入处理器；解决「字在输入框里、计数器仍 0/300、发送按钮置灰」的组件状态脱节问题，面板可关闭。
- **鱼泡防重复填充**：写入前强制清空，写入后按「精确等值」校验而不是「包含」；`execCommand` 变成追加时会立即用精确写入纠正。每次填充只保留 1 份预设，历史职位/复用聊天窗均不会叠加。
- **鱼泡 300 字校验**：按输入框 `maxlength`（默认 300）截断超长预设，避免平台长度校验拒绝导致发送失败。
- **多目标卡片点击 + 详情切换校验**：点击卡片后校验右侧详情是否已切到当前职位；未切换时换目标重试（内层节点 / 标题链接 / 卡片根 / 组件直调），仍失败则明确跳过，避免拿上一个职位的按钮做判断。
- **沟通按钮定位与点击兜底**：BOSS「立即沟通」、智联「先聊聊」、鱼泡「免费聊」按文字与作用域优先定位；合成点击被平台门禁丢弃时，自动尝试组件处理函数直调。
- **已沟通职位智能跳过**：卡片徽标（已沟通 / 沟通中 / 继续沟通等）和详情按钮文字（继续沟通 / 继续聊 / 已投递）都会触发跳过，不重复沟通。
- **自动打招呼开关**：可在面板关闭自动发送，只做职位切换与已沟通跳过（详见后文）。
- **预设话术管理**：多条预设的添加、编辑、删除、选中、随机/固定发送，持久化保存；编辑与新增共用同一套校验（trim、500 字上限、重复拒绝）和保存链路。
- **鱼泡卡片完整收集**：卡片定位按全部 XPath 取并集，并以职位链接锚点补收列表中间位置的非标准卡片（`<a>` 卡、额外包裹层、跨分组），按职位 pathname 去重，列表首/中/尾均不遗漏。
- **BOSS 跨页流程**：列表页记录待处理职位与话术，跳转聊天页后自动写入并发送，完成后返回列表继续。
- **运行可观测**：面板日志、进度（成功 / 跳过 / 失败）、页面结构诊断导出（油猴菜单）。

<summary><b>v1.10.31 新增（「管理预设话术」支持编辑已保存话术）</b></summary>

### 需求场景

原「管理预设话术」只支持添加、删除与选中：已有话术需要改几个字，只能先删除再重新输入，容易误删且操作繁琐；面板截图中的每条预设只有「删除」按钮。

### 实现方式

仅新增与「管理预设话术」相关的界面元素和操作逻辑，其余代码不做任何修改：

1. 预设条目新增「编辑」按钮（`renderPresets` 中创建 `.jd-preset-edit`，插在「删除」之前）；点击时 `stopPropagation`，不会顺带切换选中条目，运行中与删除按钮同步禁用。

4. 保存校验与 `addPreset` 完全一致：`trim` 后为空拒绝、超过 500 字截断、与其它条目重复拒绝、内容未变则只关闭不写存储；保存仍走原有 `readAndValidateConfig → persistConfig → renderPresets` 链路，并写入面板日志「已更新第 N 条预设话术」。

<summary><b>v1.10.30 修复（鱼泡列表中间职位卡片漏收）</b></summary>

### 问题现象

鱼泡列表运行日志中，第 1 条职位处理完后直接显示「定位职位（第 2/13 条）：IT运维工程师」，但页面第 2 张「运维工程师 7000-8000元/月」卡片从未出现「定位职位」记录，总数却仍是 13——该卡片在候选列表中根本不存在，属于收集阶段漏收，而非处理阶段跳过。

### 根因

1. `collectCards()` 使用 `findFirstXPathPath`，只要第一条 XPath 有命中，后续路径与 CSS 兜底全部不再执行；鱼泡首条 XPath 写死了 `.../ant-spin-container/div[1]/div` 结构，位于其它分组、带额外包裹层或不是 `div`（如 `<a>`）的卡片永远收集不到。
2. `collectYupaoExtraCards()` 在首条职位链接已被主收集覆盖时直接 `return []`，只能救回列表首条非标卡，中间位置的非标卡无任何补收路径。

### 修复方式

修改范围严格限定在 `collectCards` 的卡片定位逻辑内：

1. 鱼泡改为取全部 `cardXPaths` 结果并集（其它平台仍保持「首条命中即定局」），并做嵌套去重，避免外层容器与内层卡片重复入列。
2. 新增多职位容器排除：`yupaoJobPaths(node).size > 1` 的分组/包裹层不再被当成一条职位。
3. 新增职位链接锚点全量补收：遍历列表根内 `a[href*="/zhaogong/"]`，用现有 `findYupaoCardRoot` 反查单职位卡片根，按职位 pathname 去重、按包含关系去重后并入；同时排除详情面板「查看职位」链接与脚本面板自身链接。

### 验证结果

- `node --check` 语法校验通过。
- 提取正式脚本真实 `collectCards` 执行，夹具覆盖「无链接置顶首卡 / 位于 `div[2]` 的第 2 张卡 / `<a>` 结构卡 / 多职位分组内卡片 / 尾卡 / 详情面板与脚本面板干扰链接」（13/13 通过）：
  - 修复前基线确实漏收第 2 张卡、`<a>` 卡与分组内卡片；修复后 8 张卡全部捕获，含中间第 2 张；
  - 按页面文档顺序排列，无重复、卡片间无嵌套包含、多职位容器未被当成卡片；
  - 详情面板「查看职位」与脚本面板内链接均未被误收；
  - 连续多次调用结果稳定，无累积重复；
  - 上一轮 BOSS 会话开关验证 14/14 回归通过。

### 使用注意事项

- 直接覆盖安装即可；卡片数量与顺序与页面一致，区间模式的序号也随之为准确值。

<summary><b>v1.10.29 改造（BOSS「会话与目标职位」校验改为可选开关）</b></summary>

### 问题现象

BOSS 聊天页面板日志出现「未填写招呼语：会话与目标职位不匹配…已跳过该职位」，打招呼语填入流程被跳过；实际会话头部职位与列表项存在正常差异（标题省略、文案详略、改版差异）时，`bossChatTargetMatches()` 的两处重复校验会把职位误判为不一致，整条职位被跳过并回滚已操作标记。

### 根因

v1.10.11 引入的会话一致性校验是硬编码行为：`runBossChatPage()` 在填写话术前（等待 3 秒确认）与发送前各执行一次 `bossChatTargetMatches(flow)`，任一未命中即抛 `TARGET_MISMATCH`，该职位计为跳过。该校验无法关闭，导致「详情页与列表项信息存在差异」的特殊职位全部无法正常处理。

### 改造方式

只新增配置项与面板开关，并把两处校验调用纳入开关控制，函数定义与调用链不变：

1. 新增配置项 `bossSessionVerify`（`DEFAULT_CONFIG`，默认 `true`），`sanitizeConfig` 归一化：只有显式 `false` 才关闭。
2. 跨页传递：流程初始化与 `processJob` 的 BOSS 接力 `updateFlow` 均写入 `bossSessionVerify`，聊天页实例从 `flow.bossSessionVerify` 读取。
3. 填写前校验：`if (flow.bossSessionVerify !== false)` 包裹原 3 秒确认与 `TARGET_MISMATCH` 抛错；关闭时记录日志「会话校验已关闭：跳过目标一致性确认，直接填入话术」后继续填写。
4. 发送前校验：同样受开关控制（`flow.bossSessionVerify !== false && !bossChatTargetMatches(flow)`）。
5. 面板新增「BOSS 会话与职位校验」开关（`jdBossSessionVerify`，仅 BOSS 平台显示）：勾选状态即时持久化并回显，运行期间随控件禁用；未勾选时日志提示存在发错会话风险。
6. `TARGET_MISMATCH` 的「回滚已操作标记」逻辑保留不变——开关开启时误判跳过的职位下次仍可正常处理。

### 验证结果

- `node --check` 语法校验通过。
- 从正式脚本按名提取真实 `runBossChatPage` / `sanitizeConfig` / `DEFAULT_CONFIG` 源码执行验证（14/14 通过）：
  - 开关缺省（旧流程无该字段）+ 会话不匹配 → 仍抛 `TARGET_MISMATCH`、计为跳过、回滚标记（向下兼容）；
  - 显式开启 + 不匹配 → 与原逻辑一致；开启 + 匹配 → 正常发送；
  - 关闭 + 不匹配（详情页与列表项差异场景）→ 跳过校验直接填入发送，日志提示「会话校验已关闭」，不回滚标记；
  - 关闭 + 匹配 → 正常发送；
  - `sanitizeConfig`：默认值为 `true`，显式开/关均被保留（旧配置无该字段时自动兼容为开启）。
- 与备份（`backup/job-auto-greet.v1.10.28-20261111-pre-sessiontoggle.user.js`）对比，改动为 +53/−13 行，全部落在 BOSS 会话校验开关相关代码，职位筛选/遍历/智联/鱼泡逻辑零改动。

### 使用注意事项

- 直接覆盖安装即可；开关默认开启，行为与原版完全一致。
- 若详情页与列表项存在正常差异导致职位被误跳过，在面板「更多设置」中取消勾选「BOSS 会话与职位校验」；关闭后不再拦截会话与职位不一致的情况，请确认列表页发起时目标职位准确，避免发错会话。

<summary><b>v1.10.28 修复（移除 BOSS「右侧详情与当前职位不一致」跳过，避免误跳过未沟通职位）</b></summary>

### 问题现象

BOSS 列表运行中出现大量「跳过当前职位：右侧详情与当前职位不一致，已跳过以避免发错 HR」，实际未沟通的职位被成片跳过，任务很快以「没有更多可处理的职位卡片」结束（面板显示成功 1、跳过 1 后即停止）。

### 根因

v1.10.11 引入的 `bossDetailMatchesCard()` 要求右侧详情头部必须命中卡片链接 **或** 标题全文（≥6 字）才放行，否则直接 `SKIP`。该假设是「列表刷新/懒渲染时可能残留上一职位的详情」，但实机确认 BOSS 实际行为是：点击「立即沟通」后返回列表，已点击职位会自动从列表消失，不存在用残留详情发给上一个 HR 的场景。而列表项与详情头部存在正常差异（标题被截断、改版文案、懒渲染未完成）时，该严格比对必然失败，导致未沟通职位被误跳过。

### 修复方式

只删除列表侧该跳过校验及其专用函数，其余逻辑不变：

1. 删除 `processJob()` 中的校验块：
   ```js
   if (platform.key === 'boss' && !bossDetailMatchesCard(card)) {
     throw makeError('SKIP', '右侧详情与当前职位不一致，已跳过以避免发错 HR');
   }
   ```
2. 删除仅被该校验使用的 `bossDetailMatchesCard()` 函数（移除后无任何引用）。
3. 以下保护全部保留：
   - 详情切换校验 `ensureDetailSwitched()`（卡片点击后详情是否切到当前职位）；
   - 聊天页发送前的会话一致性校验（`TARGET_MISMATCH`，真正防止发错 HR 的兜底）；
   - 已沟通卡片/按钮文字跳过、自动打招呼关闭跳过、无沟通按钮 `NO_ACTION` 等原有判定。

### 验证结果

<summary><b>v1.10.27 修复（智联弹窗关闭失败残留遮罩，改为两种方式交替重试）</b></summary>

### 问题现象

智联点击「先聊聊」后弹出「已向对方发送打招呼语」结果层（含「留在此页」「继续沟通」按钮与右上角「×」），面板日志显示「已关闭残留的智联聊天窗口」但弹窗实际仍在，全屏遮罩残留导致后续卡片点击被拦截，任务停止后需手动关窗。

### 关键证据

实机 DevTools 截图显示「留在此页」按钮的稳定结构：

```html
<div class="deliver-greeting-modal__footer" data-v-7380196b>
  <button type="button" class="deliver-greeting-modal__btn deliver-greeting-modal__btn--secondary" data-v-7380196b>留在此页</button>
```

面板日志时序：「已关闭残留的智联聊天窗口」后弹窗仍可见，说明 closeChat 未真正生效。

### 根因

1. **closeChat 走合成点击**：`safeClick → humanClick` 通过 `dispatchEvent` 派发 MouseEvent 序列，而 v1.10.3 已实测智联门禁会静默丢弃合成点击（仅原生 `.click()` 可穿透）。closeChat 关闭结果弹窗时点击被丢弃，却无条件打印成功日志。
2. **守卫不复核**：`guardZhaopinPopup` 的聊天窗分支调用 closeChat 后直接 `return true`，不确认弹窗是否真的消失。
3. **重试不换方式**：旧 `closeZhaopinGreetingPopup` 每轮都经 `findZhaopinPopupCloseTarget` 取「×」图标为首选目标——「×」点击未生效时下一轮仍点同一个「×」，永远不会尝试「留在此页」按钮。

### 修复方式

只调整智联弹窗关闭相关代码，其余业务逻辑不变：

1. 新增 `findZhaopinPopupStayButton()`：「留在此页」按钮定位——优先实机 class（`deliver-greeting-modal__btn--secondary`），文案须为「留在」开头（留在此页/留在+城市名），绝不误点「继续沟通」；class 改版时按「留在」前缀 XPath 与固定文案兜底。
2. 重写 `closeZhaopinGreetingPopup()`：
   - **显式等待**（约束 3）：点击前等待弹窗完全加载且至少一种关闭方式可交互（最多 2 秒），慢加载/淡入动画场景不再空点或空按 Esc；
   - **两方式交替重试**（约束 4）：偶数轮点「留在此页」、奇数轮点「×」，共 4 轮；本轮首选方式未定位到目标时同轮换另一种，两种都失效才 Esc；
   - **异常捕获与降级**：每次点击 try/catch 包裹，原生 `.click()` 不可用或抛错时自动降级 `safeClick` 完整序列，再失败交给下一轮换方式；
   - 关闭确认等待 1.2 秒/轮，确认消失后追加 320ms 遮罩消散余量；终局 Esc 兜底带 800ms 确认等待。
3. 强化 `guardZhaopinPopup()`：closeChat 后必须复核——弹窗仍存在时不再假定已关闭，改走「留在此页 / ×」两方式原生点击链路（修复根因 1、2）。
4. `findZhaopinGreetingModalBox()` 结构识别兼容 `__btn`/footer 变体；智联 `closeXPaths` 补充 `deliver-greeting-modal__btn--secondary` 表达式，供 closeChat 关窗链路复用。

### 验证结果

- `node --check` 语法校验通过。
- jsdom 功能验证（从正式脚本按名提取真实函数源码执行，非复刻逻辑）：12/12 通过——
  - 「留在此页」路径、「×」路径单独可用时均能关闭（两种关闭路径验证）；
  - 首选方式点击未生效时自动换另一种方式关闭（重试兜底验证）；
  - 按钮延迟 600ms 渲染的慢加载场景下显式等待后关闭（不同加载速度验证）；
  - 原生 `.click()` 不可用时降级 `safeClick` 仍能关闭（异常捕获验证）；
  - 两种方式全部失效时如实返回 `false`、无异常、两种方式各重试两轮；
  - closeChat 后弹窗残留时守卫复核并改走两方式链路成功关闭（截图一场景回归验证）；
  - 无弹窗快路径立即返回，不拖慢循环节奏。
- 与备份（`backup/job-auto-greet.v1.10.26-20261109-pre-fix2.user.js`）对比，改动仅涉及智联弹窗函数区与智联 `closeXPaths`，BOSS / 鱼泡逻辑零改动。

### 问题现象

截图显示：聊天窗输入框已有完整预设话术，右下角仍是 `0/300`，发送按钮为灰色；面板最后可见的日志为「处理异常（不计为跳过）：未能确认打招呼语发送成功」。

3. `execCommand` 不可用或组件仍未接收时，恢复 DOM 文本，再回退到 v1.10.23 的「带 `data` 的 input + 直调 React/Vue 处理器」链路；

### 排查范围

完整梳理 BOSS 打招呼链路：列表页点击「立即沟通」→ 跳转 `/web/geek/chat` → 会话目标绑定校验 → 等待输入框 → `setEditorValue()` 填充 → 等待发送按钮 → 点击发送 → 发送结果确认（输入框清空/回车重发）→ 返回列表续跑。重点检查内容拼接、重复发送校验与自动补全。

### 排查结论

**存在同类追加问题，但有触发条件。** 空白聊天框不受影响；当聊天框在填充前已经含有草稿、上次未发内容或历史残留文本，且编辑器把 `execCommand('insertText')` 当作“在光标处追加”而不是替换选区时，实际发送内容会变成「旧内容 + 预设」。

- 旧版 `setEditorValue()` 对 contenteditable 的写入校验只判断“内容包含预设前 8 字”，追加后的内容同样包含，因此被误判为写入成功。
- BOSS 聊天页填充后只检查“输入框非空”，没有校验内容是否等于预设，于是把「旧内容 + 预设」直接发出。
- 同类情况下，如果输入框预置了 2 份预设，会发送 3 份；如果用户编辑过草稿，会把编辑内容一并发出。

### 复现路径

1. 打开某个 BOSS 职位会话，在输入框保留一段草稿/旧内容（不发送）。
2. 通过列表页流程进入该职位聊天页，脚本自动填入预设。
3. 编辑器将 `insertText` 处理为追加 → 输入框变成「草稿 + 预设」。
4. 脚本点击发送 → HR 收到带旧内容的拼接消息。
5. 若输入框已预置 2 份预设，则发送 3 份。

模拟环境（jsdom + execCommand 追加）复现结果：空白输入正常；残留草稿发送 30 字（预设 25 字）；预置 2 份发送 75 字（3 份）；编辑过的旧内容发送 39 字。

### 影响范围

- 仅 BOSS 聊天页；智联、鱼泡不经过该填充链路。
- 仅在聊天输入框非空且编辑器追加写入时触发；全新空会话正常。
- 正常跨职位流程每个职位打开独立会话，通常不会跨职位累积；但同一会话重复进入、存在草稿或上次发送未清空时可能叠加。

### 附带发现：回车重发可能导致重复消息

旧逻辑在点击发送后若输入框仍未清空，会按 Esc/回车兜底重发。如果平台实际已发送成功但保留了输入框内容，回车会把同一条消息再发一次。v1.10.15 用「消息气泡数变化」区分“未发送”与“已发送未清空”，严格模式下不再盲目回车重发。

### 修复方式

- **填入前清空**：`clearBossChatEditor()` 先清空 textarea/contenteditable，再调用原有 `setEditorValue()`；即使 execCommand 变成追加，也只会在空白基础上得到 1 份。
- **精确等值校验**：`bossChatContentMatches()` 要求输入内容与预设完全一致（归一化后比较），不再使用“包含”判断。
- **精确重写兜底**：`writeBossChatExact()` 用原生 value setter / 转义后的 `<p>` 结构写入；`fillBossChatText()` 在写入后、延迟后各校验一次，不等值就精确重写。

### 问题现象

- **事件 data 置空**：`yupaoInputEvent()` / `dispatchYupaoInputEvents()` 的 `event.data` 固定为 `null`，避免站点把整段文本再追加进 model；受控组件统一从 `target.value/textContent` 读取完整值。
- **重复调用幂等**：同一编辑器被多个职位/多次同步复用时，内容与目标一致就跳过写入，只补事件；内容不一致则清空后精确重写，不会累加。

<summary><b>v1.10.9 「操作间隔」定义修正（卡片点击 → 卡片点击）</b></summary>

### 原实现的问题

旧版（≤ v1.10.8）的「操作间隔」不是卡片点击之间的间隔，而是**整个职位处理完成之后**的延时：

1. `runLoop` 在 `processJob` 返回后才 sleep 间隔；而 `processJob` 包含详情切换、沟通按钮点击、聊天填写、发送、关闭窗口等全部耗时。
2. 因此真实点击间隔 = 处理耗时 + 间隔 + 下一张卡片的查找/人工停顿，明显大于配置值。
3. 已沟通职位、关闭自动打招呼时的正常跳过走 `120~260ms` 快速路径，完全绕过「操作间隔」。
4. BOSS 跨页时聊天页又单独等待一整段间隔，间隔被重复叠加。

### 新实现

- 卡片点击动作结束时记录 `lastCardClickAt`，并立即计算下一次点击的绝对目标时间：
  `nextCardClickAt = lastCardClickAt + 操作间隔（含速率控制的随机/降速/休息）`。
- 下一张卡片点击前调用 `waitForCardClickSlot()`：先完成人工行为停顿，再只补齐“目标时间 - 当前时间”的剩余部分，然后才点击卡片。
- 跳过路径不再重置目标时间：已沟通/关闭打招呼的职位仍快速跳过，但下一张真正被点击的卡片仍遵守上一次点击后的间隔。
- BOSS 跨页把 `lastCardClickAt/nextCardClickAt` 写入流程状态；聊天页只等待剩余时间，不再额外等待完整间隔。
- 面板「操作间隔」下方新增说明文字，明确该定义。

### 行为变化

- 关闭「启用自动打招呼」时，卡片仍按「操作间隔」逐个点击，不再出现“同一秒处理多个职位”的情况。
- 开启速率控制时，目标间隔仍由 v1.10.8 的随机/降速/休息计算；关闭速率控制后，目标值严格落在配置的最小~最大秒数内。
- 若单个职位的处理耗时本身超过配置间隔，下一张卡片会在处理完成后立即点击（不会早于间隔，但可能晚于间隔），这是无法再压缩的物理下限。

<summary><b>v1.10.8 平滑速率控制（防风控）</b></summary>

### 背景与目标

固定节奏的「点击 → 发送 → 固定间隔」在长时间批量操作时容易形成明显的机器特征，触发平台风控（验证码、操作频繁提示、沟通上限）。本版不改动任何定位、点击、发送业务逻辑，仅在「操作间隔」和「点击前的交互节奏」两处叠加平滑策略，降低机器特征。

### 三项机制

1. **不规则随机间隔**
   - 基础区间仍由面板「操作间隔」决定（建议 ≥3 秒）。
   - 88% 的概率落在基础区间内；12% 的概率拉长到 1.5~2.1 倍；10% 的概率缩短到 0.7~0.9 倍（不降低 1 秒下限）。
   - 叠加动态倍率与休息时间后统一封顶 180 秒，避免极端配置产生超长等待。
2. **人工行为模拟**
   - 点击卡片、点击「立即沟通 / 先聊聊 / 免费聊」前：滚动到目标居中 → 悬停（pointer/mouse 序列）→ 180~620ms 阅读停顿 → 目标内随机 `mousemove` → 60~200ms 停顿。
   - BOSS 聊天页点击「发送」前同样执行。
   - 不改变点击目标、点击顺序与点击判定，只增加交互节奏。
3. **动态降速与周期休息**
   - 连续异常（非正常跳过）时，间隔倍率按 `1 + 连续异常数 × 0.6` 提升，最高 3 倍；恢复正常后每次间隔回收 0.25 倍，速度平滑回落。
   - 每 6~12 次操作间隔插入一次 4~9 秒的额外休息，模拟人工停顿。
   - 已沟通职位等「正常跳过」仍使用 120~260ms 短延迟，不拖慢列表扫描。

### 面板开关

「速率控制（防风控）」区域新增三个独立开关，默认全部开启：

| 开关 | 作用 |
| --- | --- |
| 平滑速率控制 | 控制不规则随机间隔与周期休息 |
| 模拟人工操作 | 控制点击前的悬停 / 微滚动 / 停顿 |
| 动态降速 | 控制连续异常后的间隔倍率调整 |

关闭「平滑速率控制」后完全回到旧版基础随机区间；三个开关均即时保存。

### 验证结果（jsdom 模拟 + 回归）

- 速率控制专项与兼容性用例 **21 项断言全部通过**：人工行为事件与点击间隔、关闭人工模拟后无行为事件、异常后 1.6 倍降速日志、关闭速率控制后无额外动作、三项开关持久化；区间扫描互斥、BOSS 已操作标记、鱼泡灰色发送按钮、BOSS 聊天页返回均保持正常。
- 原有回归套件 **39 项断言全部通过**（T1~T9），三平台主流程、已沟通跳过、关闭态上限、配置边界均无退化。
- `node --check` 语法校验通过。
- 说明：风控触发率无法在模拟环境中量化，本次验证的是「节奏确实被随机化/拉长、原有功能不变」；建议实机以 3~6 秒间隔连续运行 20~30 个职位，观察是否仍出现验证码或频繁提示。

### 兼容性说明

- 默认行为变化：升级后默认开启三项速率控制，整体耗时会比旧版增加约 20%~60%（视职位数量与随机分布），属预期。
- 如需恢复旧版速度，可在面板关闭三项开关，间隔逻辑与旧版一致。
- 不引入任何依赖；仅使用 `Math.random`、现有延时函数与 DOM 事件派发。

<summary><b>v1.10.7 修复（BOSS 聊天页无法返回职位列表）</b></summary>

### 问题现象

BOSS 职位列表点击「立即沟通」后正常跳转 `/web/geek/chat`，聊天页完成填写与发送，面板日志显示「已发送打招呼语」并进入「等待后返回列表」，但页面始终停在聊天页，无法继续处理后续职位。

### 根因

旧版聊天页发送完成后只执行 `history.back()`，把「返回列表」交给浏览器历史。BOSS 进入聊天页可能使用 replace 路由或在新标签页打开：

- 新标签页打开：当前标签页 `history.length === 1`，`history.back()` 无任何效果；
- replace 打开：后退可能离开聊天页，但目标不保证是原职位列表；
- 部分浏览器对 SPA 路由的后退恢复不完整，列表不会重新渲染。

因此必须显式回到已知的列表地址，而不能依赖历史栈。

### 修复方式

- 列表页启动任务时，把当前完整列表地址（`location.href`，含 city/query 等筛选参数）、滚动位置 `scrollY` 与「自动返回」开关写入 BOSS 跨页流程状态；每次点击「立即沟通」前再刷新一次（此时卡片已滚动到可视区）。
- 聊天页发送完成后新增 `returnToBossList()`：优先 `location.assign(列表地址)` 显式导航，目标与原列表完全一致，筛选条件天然保留；`location.href` 作为 assign 异常时的兜底；`history.back()` 仅在旧流程没有地址记录时使用。
- 返回列表后新增 `restoreBossListScroll()`：卡片渲染后调用 `window.scrollTo(0, 保存的 scrollY)` 恢复滚动位置；若新一轮处理已经产生结果则停止恢复，避免抢走当前职位的位置。
- 面板新增「BOSS 聊天页发送后自动返回列表」开关，仅 BOSS 平台显示、默认开启。关闭后发送完成停留在聊天页并提示手动返回，流程状态仍保留，手动返回列表后继续续跑。
- 使用的均为浏览器标准接口（`location.assign` / `location.href`、`history.back`、`window.scrollTo`），不引入任何依赖，Chrome / Edge / Firefox 行为一致。

### 验证结果（jsdom 模拟）

- 新增用例 **20 项断言全部通过**：有 listUrl 时显式导航到原列表地址且不再调用 `history.back()`；无 listUrl 时正确回退到浏览器后退；关闭开关后不导航；列表页流程写入 `listUrl/scrollY/autoReturn`；返回后恢复滚动位置；开关仅 BOSS 显示且正确持久化。
- 原有回归套件 **39 项断言全部通过**（T1~T9），三平台主流程、已沟通跳过、关闭态上限、配置边界均无退化。
- `node --check` 语法校验通过。
- 说明：jsdom 不支持真实页面导航，用例通过「导航调用 + 目标地址日志」验证；建议在 Chrome / Edge / Firefox 各实机跑 1 个职位，确认返回与续跑表现一致。

### 5. 后续维护注意事项

1. **XPath 作用域**：新加的 XPath 仍可写 `//`，传入元素根时会改写成 `.//`；如果表达式引用根节点自身（如 `//div[@id="mainR"]//button`），会自动回退到文档级查询 + `root.contains`。为减少回退开销，新增作用域路径优先写 `.//`。
2. **卡片稳定 key**：新增无职位链接的平台时，务必补充 `keySelectors`（标题、薪资、公司、地区等稳定字段），不要把整个卡片文本或状态徽标纳入 key；状态词统一维护在 `communicatedTexts`/`skipActionTexts`，`stripStatusWords` 会自动剔除。
3. **发送确认**：不要恢复“按钮还在就直调 React”的旧逻辑；发送按钮在成功后通常仍留在 DOM，必须用 `isSent`/`waitSent` 确认。否则会重新引入重复发送风险。
4. **聊天面板缓存**：`cachedChatPanel` 在 `closeChat` 中清空；新增关闭路径时也要清空，避免下一次动作把已关闭面板误判为“已打开”。
5. **登录缓存**：`detectLogin` 缓存 600ms；登录浮层出现/消失的检测最多延迟一个轮询周期。若页面存在极短闪现的登录层，可缩短缓存或改为只在 `waitForChat` 内使用短缓存。
6. **React 键名缓存**：`reactKeyCache` 只缓存 `__reactProps$`/`__reactFiber$` 的键名，不缓存 props 对象；若页面在运行中重新水合且键名变化，清空缓存或刷新页面。
7. **框架直调重试**：`hasFrameworkBinding` 当前识别 React/Vue 键；新增 Svelte/Solid 等框架时，要么扩展探测，要么为该平台强制启用直调重试。
8. **跳过与间隔**：短延迟只用于 `SKIP`（已沟通/关闭态跳过），成功发送和真实失败仍使用用户设置的 3–6 秒间隔；不要为了提速把短延迟套到所有异常上。
9. **关闭态上限**：关闭自动打招呼时用 `sent + skipped` 计数并在本轮结束立即退出；若调整跳过统计口径，需要同步修改这个条件。
10. **存储策略**：GM 为主写，localStorage 仅兜底/迁移；如果外部工具依赖 localStorage 镜像，请显式增加镜像写入，不要恢复热路径双写。
11. **测试维护**：T8/T9 依赖 UI 字段 `#jdMinInterval/#jdMaxInterval`、日志「定位职位（第 N/总数 条）」和无链接卡片结构；修改这些文案/结构时同步更新 `verify.mjs`。
12. **版本与文件**：主脚本内部版本为 `1.10.4`，文件名保留 `v1.10.3` 以便直接覆盖安装；Tampermonkey 会按 `@version` 识别升级。

<summary><b>v1.10.2 修复（智联卡片点击门禁——Vue 直调三通道）</b></summary>

### 问题定位（基于 2026-11-06 智联实机 DOM dump）

- 智联列表页对合成点击设了门禁：脚本派发的 pointer/mouse/click 全序列被静默丢弃，右侧详情纹丝不动（与 BOSS/鱼泡同路数）。

- 卡片标题是纯 span（`.vue-clamp__text`），卡片上没有职位链接，BOSS 同款「跳 href 跨页」兜底在智联无路可走，必须正面攻克点击。

### 修法：Vue 侧直调三通道（v1.10.2）

此前只探测 React 系与 Vue 组件 props 两类绑定。Vue 系事件其实还有三条 DOM 可见通道，本次全部接入直调链（伪造事件 isTrusted=true 可过组件内门禁检查）：

1. **`_vei` 调用器表**：Vue 3 模板 `@click` 以调用器表挂在元素属性 `_vei` 上，节点 + 祖先 6 层 + 子级 40 个逐点探测，找到即以伪造事件直调；
2. **Vue 3 组件树**：`__vueParentComponent.subTree` 沿 vnode 树找 `props.onXxx` 绑定；
3. **Vue 2 组件树**：`__vue__._vnode` 沿树找 `data.on` 绑定。

接入位置：卡片点击重试梯子（ensureDetailSwitched）与沟通按钮兜底链（invokeActionFallback）各加两级；直调执行时在面板日志输出「Vue 直调已执行（onClick@DIV.job-card …）」明示调用明细。

「导出页面结构（诊断）」新增一段：报告卡片向上 6 层 / 向下 60 个子级上的全部框架绑定键分布；若通通没有，会明确给出结论「事件极可能以原生 addEventListener 命令式绑定（直调不可达），需走事件拦截方案」——为下一轮修复方向提供判决依据。

### 回归验证（jsdom 模拟，36 项断言全部通过）

- **新增 T7 门禁用例**：卡片事件经 `_vei` 调用器绑定且处理函数校验 `isTrusted === true`（文档级对合成点击零响应）——v1.10.2 的 Vue 直调以伪造事件攻破门禁，完成详情切换与「先聊聊」发送（成功 1，跳过 0）；**同场景对 v1.10.1 对照：直调无目标、详情纹丝不动、任务未完成**（缺陷复现实锤）。

### Bug1：左侧职位卡片点击失效、右侧详情不切换

### Bug2：BOSS「立即沟通」、智联「先聊聊」点不动，鱼泡「免费聊」定位错

- **nativeEvent 用真实事件对象**：伪造事件里 `nativeEvent` 此前是 `null`——处理函数若读取 `e.nativeEvent` 的任何属性（Next.js/极验环境常见）会中途抛错并被静默吞掉，表现正好是「处理函数调用了但页面毫无反应」。现在 nativeEvent 是一个真实的 `MouseEvent/KeyboardEvent/PointerEvent` 实例，且实例上用 `Object.defineProperty` 遮蔽 `isTrusted` 为 `true`、补齐键盘事件的 `keyCode/which/charCode`。

## XPath 定位策略

脚本统一以 **XPath 主定位**，CSS 选择和文字匹配只作兜底。平台改版时优先在脚本顶部 `PLATFORM_DEFS` 的 `cardXPaths`、`actionXPaths`、`detailXPaths`、`detailPanelSelectors`、`inputXPaths`、`sendXPaths`、`closeXPaths` 中补充表达式。

v1.10 的关键定位：

- BOSS「立即沟通」按钮：
  `//a[contains(@class,"op-btn-chat") and contains(normalize-space(.),"立即沟通")]`
- BOSS 聊天输入框 / 发送按钮：
  `//div[@id="chat-input"]` / `//div[contains(@class,"chat-op")]//button[contains(@class,"btn-send")]`
- 智联沟通按钮（文字优先，不再取 `button[1]`）：
  `//div[contains(@class,"job-detail-summary__actions")]//button[contains(normalize-space(.),"先聊聊")]`
  其后依次为「立即沟通」「继续沟通」，并使用 `not(contains(.,"投递"))` / `not(contains(.,"申请"))` 排除投递类按钮。
- 鱼泡卡片：
  `//div[contains(@class,"ahjb")]//div[contains(@class,"ant-spin-container")]/div[1]/div`
- 鱼泡「免费聊 / 聊一聊 / 继续聊」按钮（先限 `#mainR` 详情作用域，全局文字仅兜底）：
  `//div[@id="mainR"]//*[normalize-space(text())="免费聊" or normalize-space(text())="聊一聊" or normalize-space(text())="继续聊"]`
- 鱼泡聊天输入框 / 发送按钮：
  `//div[contains(@class,"fb-editor") and @contenteditable="true"]` / `//button[contains(@class,"btn-send")]`

## 打招呼语预设管理

面板中的「打招呼语预设」支持：

- **选择**：点击某条预设即可设为当前模板，标记为「使用中」；同时自动取消随机模式。
- **添加**：输入新话术，点击「添加预设」；也支持 `Ctrl + Enter`。
- **删除**：点击每条预设右侧的「删除」；至少保留一条。删除当前选中项前面的条目时，选中下标会自动前移，保持仍选中原来那条话术。
- **随机模式**：勾选「循环时随机使用」后，每个职位从预设列表随机选取，并避免连续两次使用同一条。
- **固定模式**：取消勾选后，固定使用当前选中的预设。
- 预设保存到 Tampermonkey 存储，刷新页面后保留；最多 50 条，每条最多 500 字。

## 「启用自动打招呼」开关

位置：面板「打招呼语预设」下方，复选框「启用自动打招呼」。

| 项目 | 说明 |
| --- | --- |
| 默认值 | 开启（与 v1.9 行为一致） |
| 持久化 | 与其他配置一起保存到 Tampermonkey 存储，刷新后保留 |
| 开启时 | 正常点击沟通按钮、写入预设话术并发送 |
| 关闭时 | 仍切换卡片、校验详情、跳过已沟通职位；不点击沟通按钮、不写输入框、不发送 |
| 关闭时的停止条件 | 已处理职位数达到「处理数量」后停止（不是发送成功数） |
| 运行中修改 | 运行期间开关被禁用，需停止后修改 |

适用场景：

- 只想浏览/筛选职位，不想发送任何消息；
- 先让脚本帮你把已沟通职位和详情切换走一遍，确认页面与定位正常，再开启发送；
- 平台风控敏感期，只保留浏览与跳过逻辑。

注意：关闭后「成功发送」计数不会增加，面板进度会以「跳过」为主；这是预期行为，不是脚本卡死。

## 安装与升级

### 全新安装

1. 安装 Tampermonkey（油猴）扩展。
2. 点击 Tampermonkey 图标 →「添加新脚本」。
3. 清空编辑器内容，粘贴 `job-auto-greet.v1.10.31.user.js` 全部代码。
4. `Ctrl + S` 保存并确认脚本已启用。
5. 打开支持的职位列表页，右下角出现「自动沟通助手」面板。

### 从 v1.9 或更早版本升级

1. 打开 Tampermonkey 管理页，找到原脚本 →「编辑」。
2. 用 `job-auto-greet.v1.10.31.user.js` 的内容整体替换旧代码，`Ctrl + S` 保存。
3. 刷新目标平台页面（建议直接 F5，避免旧实例残留）。
4. 打开面板确认版本行为：应能看到「启用自动打招呼」复选框；原预设、处理数量、间隔等配置会自动沿用。

说明：

- 存储键未变（`jd_auto_greet_config_v1`），升级不会清空已有预设和配置。
- 新配置项「启用自动打招呼」在旧配置中不存在时按**开启**处理，无需手动迁移。
- 若同时保留旧版脚本，请禁用其中一个，避免两个实例同时操作页面。

## 使用步骤

1. 登录目标平台，打开职位列表页并等待卡片加载。
2. 在面板中选择/添加/删除预设话术，设置操作间隔，并按需选择扫描范围：`循环模式` 填「处理数量」，或 `区间模式` 填「第 N ~ M 条」（两者只能开启一项）；按需勾选/取消「启用自动打招呼」与「速率控制（防风控）」三项开关。预设管理、扫描范围、速率控制等位于「管理预设话术」「更多设置」折叠区，点击标题即可展开。
3. 点击「保存配置」；直接点击「开始」也会先保存当前参数。
4. 点击「开始」：循环模式从列表第一条未处理职位开始依次处理；区间模式只处理指定区间内的职位，区间外自动跳过。已沟通职位始终自动跳过。
5. 开启打招呼时，成功发送数量达到目标后自动停止；关闭打招呼时，处理职位数达到目标后停止。区间模式的目标为区间内职位数。需要中断时点击「停止」。

执行期间请保持浏览器窗口在前台。窗口最小化或切到后台会触发浏览器定时器节流，脚本等待会明显变慢。

## 限制与注意事项

- **操作间隔**：面板允许 1–120 秒；脚本会把最小值限制在 1 秒以上、最大值自动抬到不小于最小值。默认 3–6 秒，低于 3 秒会明显提高触发平台风控的概率。
- **处理数量**：1–200，默认 20。开启打招呼时按「成功发送」计数；关闭时按「已处理职位」计数。
- **区间扫描**：序号按当前页面列表的显示顺序（从上到下）统计；如需处理后续分页职位，请先滚动加载再开始。区间模式与循环模式互斥，切换模式会立即保存配置。
- **BOSS 已操作标记**：点击「立即沟通」即写入本地标记（最多 800 条，按时间淘汰），之后同一职位会被自动跳过。如需重新处理某个已标记职位，需要在油猴存储中清除 `jd_auto_greet_boss_marks_v1`（或清除该站点的脚本数据）。
- **BOSS 自动返回**：返回使用任务开始时记录的列表完整地址，筛选条件随地址保留；滚动位置在新列表渲染后恢复。若 BOSS 在新标签页打开聊天页，返回后可能同时存在多个列表页，请只保留一个运行脚本的列表页，避免重复处理。
- **鱼泡发送按钮**：脚本会优先让站点自身恢复按钮可用态，仍为灰色时强制解除禁用再发送；若站点内部状态仍拒绝发送，会按发送失败跳过并在日志中提示，不会重复发送。
- **速率控制与耗时**：默认开启三项防风控开关，单职位耗时会比旧版增加约 0.3~1 秒，且每 6~12 个职位额外休息 4~9 秒；需要更快节奏时可在面板关闭，但风控概率会上升。
- **操作间隔口径**：间隔从上一张卡片点击动作结束开始计时，到下一张卡片点击动作开始为止；已沟通/关闭打招呼的跳过不会重置该计时。若单个职位处理耗时超过间隔，下一张卡片会在处理完成后立即点击。
- **风控无法完全避免**：速率控制只降低机器特征，不保证不触发平台风控；仍建议基础间隔 ≥3 秒、单次任务不超过平台日常沟通量，并避免多标签页同时运行。
- **每日上限**：脚本本身没有本地每日计数器；每日可沟通数量由平台账号限制决定。达到平台上限后，平台通常会给提示或直接失败，脚本会按失败/跳过处理并可能停止。
- **BOSS 跨页流程有效期**：未完成的流程超过 **15 分钟** 不再自动续跑，避免隔夜残留误接管。
- **单标签页限制**：BOSS 跨页流程状态保存在浏览器本地存储，同一浏览器请只保留**一个**运行脚本的列表页标签页。同时开多个标签页可能出现两个实例互相接管或重复处理；脚本没有强抢锁机制，这一点需要人工避免。
- **窗口状态**：保持浏览器前台，避免定时器节流导致等待变慢。
- **不绕过风控**：遇到登录、验证码、频率限制会停止或跳过，不做绕过。

## 脚本工作流程

1. 用 XPath 扫描职位卡片，并按文档位置从上到下排序。
2. 跳过 `state.processed` 中已处理的职位（含 BOSS 本地已操作标记与区间模式下的区间外职位），取第一条未处理卡片。
3. 滚动到卡片并触发悬停（速率控制开启时先执行人工行为停顿）；按平台的多目标顺序点击卡片，切换右侧详情：
   - BOSS：内层 `li.job-card-box` / `.job-card-box` / 左侧区 / 标题 → 卡片根，点击后校验右侧详情已切到当前职位。
   - 智联：标题 `.job-card__name` 等 → 卡片根；同样校验详情切换。
   - 鱼泡：标题链接 → 卡片根（`safeClick` 阻止链接跳转），校验详情头部标题。
4. 点击后未切换时，按重试梯子换目标重试；仍失败则明确跳过，不读取旧详情的按钮。
5. 已沟通判定：卡片徽标（已沟通 / 沟通中 / 继续沟通 / 继续聊 等）命中即跳过，点卡片前就会生效。
6. 定位沟通按钮：按平台文字优先级选取；命中投递/申请/发送简历类按钮一律排除。
7. 若「启用自动打招呼」为关闭状态：到此为止，计为跳过并处理下一张卡片。
8. 点击沟通按钮（速率控制开启时点击前同样有悬停与停顿）；未打开聊天/结果弹窗时，尝试组件处理函数直调兜底。
9. 等待聊天弹窗、抽屉或输入框出现；若显示「已向对方发送打招呼语」等结果弹窗，直接按成功计数。
10. 写入本次选中的预设话术，并触发 `input/change` 事件；鱼泡平台在发送前额外检测发送按钮，灰色不可用时先执行灰色按钮适配。
11. 优先点击「发送」，找不到按钮时尝试回车；验证输入框清空或消息出现。
12. 关闭聊天窗口；BOSS 聊天页发送完成后按记录的列表地址返回（可在面板关闭），再按「上一张卡片点击结束 → 下一张卡片点击开始」补齐间隔后处理下一张卡片。
13. 达到设定阈值立即停止；当前页无新职位时滚动到底部尝试加载更多，仍无则结束。

## 平台差异与实测结构

### BOSS直聘

- 列表为「左侧卡片 + 右侧详情面板」；卡片本身没有沟通按钮。
- 点击卡片内层可点击节点（`li.job-card-box`、`.job-card-box` 或标题）切换详情，右侧 `.job-detail-box` / `.job-detail-container` 中出现 `a.op-btn.op-btn-chat`（「立即沟通」）。v1.10 会校验详情是否真的切换，并支持多目标重试。
- 点击沟通后跳转独立聊天页 `/web/geek/chat`；输入框 `#chat-input`（contenteditable），发送按钮 `.chat-op .btn-send`（空内容时带 `disabled`）。
- 跨页状态机：列表页记录待处理职位、列表地址、滚动位置和本次话术 → 聊天页自动填写发送 → 返回原列表地址（v1.10.7 起显式导航，旧版为 `history.back()`）→ 自动续跑下一职位。状态保存在 Tampermonkey 存储；超过 15 分钟未完成不会自动续跑。
- v1.10.6 起，点击「立即沟通」前会额外写入本地已操作标记（`jd_auto_greet_boss_marks_v1`）；返回列表页或下次重新开始时，已标记职位直接跳过，避免重复进入聊天页。
- v1.10.11 起，点击「立即沟通」前要求详情严格匹配当前卡片；聊天页填写/发送前校验当前会话与 `pendingKey/pendingTitle` 一致，不一致会停止发送并回滚标记，避免把消息发给上一职位的 HR。
- v1.10.12 起，区间目标按职位元素（pathname）快照定位，不再依赖实时下标；返回列表后已沟通职位被动态移除也不会错位。卡片处理前会检查连接状态，失效时按 key 重新定位；返回列表后最多等待 6 秒让卡片渲染。第 2 个职位起跳转聊天页不再误标流程完成，聊天页可正常接管发送。
- v1.10.15 起，聊天页填入前先清空草稿/残留内容，填入后按精确等值校验并同步 React 状态；发送前再次校验，内容与预设不一致时停止发送。发送后若输入框未清空，会先检查是否出现新消息气泡，避免把「已发送未清空」误判为失败后回车重发。面板可关闭「BOSS 输入精确校验」。
- v1.10.7 起，点击「立即沟通」前同时记录列表完整地址与滚动位置；聊天页发送完成后显式返回该地址（保留筛选参数）并恢复滚动位置，然后续跑下一职位。自动返回可在面板关闭。
- 若流程状态标记了「自动打招呼已关闭」，聊天页不会发送，计为跳过并返回列表。

### 智联招聘

- 列表页 `.job-card` 点击后更新右侧详情面板；v1.10 会校验详情确实切换到当前职位。
- 操作区按钮按文字优先：先「先聊聊」，再「立即沟通」，再「继续沟通」；`立即投递 / 立即申请 / 投递简历` 一律不点。只有投递按钮的职位会按「未找到沟通按钮」跳过。
- 已沟通职位显示「继续沟通 / 已投递」，脚本按正常跳过处理，不发送。
- 新职位点击「先聊聊」后，平台自动发送自带招呼语，并出现「已向对方发送打招呼」结果弹窗。v1.10.12 起不再依赖 `.deliver-greeting-modal` 等易变 class，而是按「留在此页」按钮 + 结果文案做文字级检测；优先点「留在此页」停留当前页，失败时尝试关闭图标或按 Esc，并轮询确认弹窗消失。每轮循环开始前还会兜底清理残留弹窗，可在面板关闭该兜底开关。
- 脚本不会进入或操作智联「设置招呼语」页面；检测到「添加招呼语 / 设为默认」且无职位卡片时不注入面板，避免误触导致自动发送。
- 智联网页版默认使用平台自带招呼语；本地面板选中的预设只在出现可编辑聊天输入框时写入。

### 鱼泡直聘

- 真实页面为「左侧 `.ahjb` 卡片列表 + 右侧 `#mainR` 详情」；卡片位于 `.ant-spin-container > div:first-child` 下。
- 详情头部按钮为「发送简历 / 免费聊 / 拨打电话」；已沟通职位显示「继续聊」。脚本只点「免费聊 / 聊一聊 / 继续聊」，并先限定在 `#mainR` 详情作用域，避免命中左侧列表或底部推荐位里的同名节点。
- 点击后打开 ant-drawer 聊天抽屉：输入框 `.fb-editor`（contenteditable 或内部 textarea），发送按钮 `.btn-send`（文字「发送」）。
- v1.10.6 起，若预设文本已写入但 `.btn-send` 仍为灰色，脚本会补发输入事件、同步组件 `onChange`，仍不可用时解除 `disabled` 属性/类后再点击发送。
- v1.10.13 起，输入改为「真实编辑器解析 + execCommand + 完整事件序列 + Vue/React 输入处理器直调」；对应截图中「字已写入、计数器仍 0/300、发送按钮置灰」的组件状态脱节问题。输入上限按 `maxlength`（默认 300）截断超长预设。面板可关闭「鱼泡输入同步增强」。
- v1.10.14 起，写入前强制清空、写入后按精确等值校验并在不等值时精确重写，修复「切到下一个职位时预设被填充 2~3 次」的重复堆叠问题。
- v1.10.17 起，循环模式会补充收集虚拟列表之外的置顶/首条职位卡片（兼容 `<div>` / `<a>`），并按文档顺序排到索引 0，确保从页面第一条职位开始遍历。
- v1.10.18 起，首条置顶卡即使没有 `zhaogong` 链接，也会按“第一张主卡片的前置兄弟”位置补收；筛选栏/推荐分组会被尺寸与职位特征词过滤，不会误插。
- v1.10.19 起，置顶/品牌卡标题不在标准 class 或链接里时，改取可视文本第一行/顶部叶子文本，避免把薪资、标签、公司名拼进标题导致详情切换校验误判；详情未切换日志会打印脚本提取到的卡片标题。
- v1.10.21 起，输入同步在 DOM 事件之外增加 `onUpdate:modelValue` 回写，解决“字已写入、计数器仍 0/300、发送按钮灰色”的 Vue v-model 模型脱节问题。
- v1.10.22 起，`.fb-editor` 内同时存在隐藏 textarea 和可见 contenteditable 时，优先写入可见 contenteditable，避免话术写进表单镜像、可见编辑器仍为空导致 0/300。
- v1.10.23 起，检测到“DOM 有字、计数器仍 0/300”时，补发带完整 `data` 的 input 并直调带 data 的 React/Vue 处理器，用计数器确认 model 更新后才点击发送。
- 关闭时优先找关闭按钮；找不到时点击 `.ant-drawer-mask` 遮罩，再按 `Esc` 兜底。
- 游客点击会弹出验证码登录拦截层，脚本会停止并提示登录。

## 关于开发者工具与反爬

- 脚本不依赖 F12：不做 DevTools 调试、不使用 `debugger`、不向 `console` 输出日志，所有定位使用页面 DOM 与 XPath。
- 脚本不绕过平台验证码、登录验证或风控系统；遇到验证/登录/频率限制会停止。
- 建议运行前关闭 F12 开发者工具，保持 3–6 秒以上操作间隔，避免短时间高频请求。
- 平台可能因账号、IP 或操作频率触发风控，脚本无法保证账号不受限制。

## 常见问题

- **面板没有出现**：确认 URL 属于支持页面且脚本已启用；部分单页应用需刷新一次。
- **BOSS 点击卡片后详情没变化**：v1.10 会依次尝试内层节点、标题与卡片根，并校验详情切换；若日志提示「详情未切换」，请刷新页面后重试，或按平台实际结构补充 `cardClickTargets` / `detailPanelSelectors`。
- **BOSS「立即沟通」点了没反应**：查看日志是否出现「合成点击未生效，尝试组件直调兜底」；若兜底仍无效，平台防护可能已升级，请提供面板日志与页面结构导出。
- **智联按钮不是「先聊聊」**：已沟通账号可能显示「继续沟通」，脚本会跳过；只有投递按钮的职位会跳过而不是投递。
- **智联自定义话术未生效**：智联网页版默认使用平台自带招呼语；只有聊天输入框出现时脚本才写入本地预设。
- **鱼泡「免费聊」点不到**：确认日志是点击右侧详情按钮；若平台改版导致结构变化，请补充 `actionXPaths` 或 `panelSelectors`。
- **鱼泡点击后没有聊天框**：脚本会等待一定时间后跳过当前职位；可检查是否登录、是否被平台限制，或补充 `panelSelectors` / `inputXPaths`。
- **鱼泡聊天抽屉关不掉**：脚本会尝试关闭按钮、`.ant-drawer-mask` 遮罩和 `Esc`；若平台改版，请补充 `closeSelectors` / `closeXPaths`。
- **开启「启用自动打招呼」后仍然不发送**：确认开关已勾选并保存；关闭时不会点沟通按钮，也不会写话术，属于预期行为。
- **关闭开关后一直跳过**：关闭状态下按「已处理职位数」停止；如果预设的「处理数量」较大，会继续扫描到该数量或列表结束。
- **达到数量后还在执行**：开启打招呼时只统计成功发送数量；失败/已沟通会跳过并继续寻找下一条，直到成功数达到目标。关闭打招呼时按已处理职位数停止。需要立即停止请点「停止」。
- **执行速度变慢**：窗口最小化/后台会触发定时器节流，请保持前台。
- **BOSS 跨页后没有续跑**：确认未超过 15 分钟流程有效期；重新从列表页点击「开始」即可。

## 风控与使用建议

- 保持默认 3–6 秒或更长间隔，不要同时开多个标签页批量运行。
- 每天沟通数量受平台账号限制，达到上限后脚本会停止或跳过失败。
- 建议先设置处理数量 1–2 做小批量验证，再增加数量。
- 自动化操作可能违反平台用户协议，存在账号被限制的风险；请仅用于个人求职，合理控制频率，并自行承担使用风险。
